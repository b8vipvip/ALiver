# 抖音直播伴侣可视互动采集器

ALiver 0.12.0 不再依赖抖音开放平台互动插件、PipeSDK、独立采集器 EXE 或 C++ 注入层。采集器直接运行在 Windows Bridge 中，只读取“抖音直播伴侣”窗口里已经向主播显示的互动文字。

## 链路

```text
抖音直播伴侣可见互动区
  -> Windows UI Automation（优先）
  -> 局部窗口截图 + RapidOCR（兜底）
  -> Bridge 去重和事件解析
  -> POST /api/douyin-live/bridge/ingest
  -> AudienceEvent
  -> 专业总导演
  -> Chrome 导演扩展
  -> ChatGPT Live
  -> VTube Studio / 直播伴侣
```

采集器不会抓包、注入直播伴侣进程、读取内存、访问 Cookie，或调用抖音未公开接口。

## 支持范围

只要直播伴侣界面出现了对应文字，就可以尝试识别：

- 评论昵称与内容；
- “某某关注了你”；
- 带昵称、礼物名称和数量的礼物通知；
- 粉丝团加入或升级通知；
- 分享提示；
- 可选的观众进入提示；
- 可选的单条点赞提示。

直播伴侣没有显示的隐藏事件、纯礼物动画、精确礼物价值、观众账号 ID 等信息无法从可视界面可靠获得，ALiver 不会伪造这些字段。

## 依赖

Windows 安装 `requirements.txt` 后会自动安装：

- `pywinauto`：读取 UI Automation 控件；
- `pywin32`：查找直播伴侣窗口；
- `mss`：截取局部窗口区域；
- `rapidocr` + `onnxruntime`：中文 OCR；
- `opencv-python`、`numpy`、`pillow`：图像处理支持。

无需构建或运行额外的采集器 EXE。

## 使用

1. 启动 ALiver 服务端、Windows Bridge、Chrome 导演扩展和抖音直播伴侣。
2. 在“自动导演”中选择 Chrome 导演扩展，保存配置并开始执导。
3. 找到“抖音直播伴侣可视互动采集器”。
4. 选择在线 Windows Bridge。
5. 保持模式为“混合：UIA 优先，OCR 兜底”。
6. 点击“自动校准互动区”。
7. 点击“保存并启动”。

配置保存在：

```text
bridge/douyin_visible_collector.local.json
```

Bridge 下次启动会自动恢复采集，无需重新填写。

## 默认 OCR 区域

针对当前常规模式布局，默认区域使用直播伴侣窗口的相对坐标：

```json
{
  "x": 0.782,
  "y": 0.405,
  "width": 0.205,
  "height": 0.555
}
```

它对应窗口右下角的“互动消息”区域。使用相对坐标后，窗口按比例缩放时通常仍能工作。直播伴侣改版或用户拖动面板后，需要重新校准或手工调整。

## 双通道规则

### UIA

UIA 能读取真实文本时，准确率高、延迟低，也不需要截图。若 UIA 只暴露“互动消息”“发送”等静态标签，系统不会误判为有效数据，而会自动启用 OCR。

### OCR

OCR 只截取互动区，不扫描整个桌面。识别出的昵称和内容即使被拆成多个文本框，也会按同一视觉行重新组合。低于置信度阈值的结果只记录为忽略，不进入总导演队列。

## 去重

同一条可见消息可能在屏幕上停留数秒。Bridge 会先做短期本地去重，服务端再按事件指纹做持久去重，避免主播连续重复回复同一评论或感谢同一礼物。

## 限制和排障

- 直播伴侣被最小化时，OCR 通常无法截图；保持窗口正常显示。
- 其他窗口完全遮住互动区时，截图内容可能受到影响。
- 活体检测、二维码验证等弹窗覆盖直播伴侣时，采集可能暂时无事件；弹窗关闭后会自动继续。
- UIA 是否能读取评论取决于直播伴侣当前版本的控件实现。
- OCR 识别不稳定时，先检查区域，再降低或提高置信度阈值。
- “原始文本”有内容但“解析后的互动事件”为空时，说明文字格式尚未匹配，可根据样本补充解析规则。
- 采集器状态、原始文本和解析事件都可以在 ALiver 页面实时查看。

## 隐私

ALiver 只把界面中已显示的昵称和互动内容用于本机直播导演。不要公开导出含观众信息的日志和支持包。
